# MathWorks adapter boundary

The official [Simulink Agentic Toolkit](https://github.com/matlab/simulink-agentic-toolkit/tree/c58e6aec7b904769ae43536e169d747feda95416) is pinned to release commit `c58e6aec7b904769ae43536e169d747feda95416` (`2026.10.a`). `upstream_pin.yaml` records exact skill, manifest, reference, tool-registration and license hashes from a live read-back on 2026-10-08. The companion MATLAB Toolkit commit is also pinned. These references do not establish a local installation.

`skill_mapping.yaml` maps actual upstream skill names to approved C needs and the frozen E protocol's execution requirements. Local contracts retain mathematical identity, traceability, parameter provenance and run acceptance. The adapter supplies reference pointers and compatibility requirements; it does not execute upstream instructions, install toolboxes, change global MATLAB paths, or grant simulation permission.

The upstream skill manifests declare R2023a or later. R2025b lies in that range, but toolkit MCP tools still require operation-specific tests on the actual channel and installed resources. The local D fallback requires independent qualification for `simulink.core_build_structure`, with six controlled block types and save/reopen/update/readback assertions. E adds a separate `simulink.core_simulation` operation and solver-specific qualification on the batch channel. A `simulink.library_load` result proves only the Phase A operation. This metadata records the available gates, rather than proving that the current host has passed them.

## Phase E reference selection

The pinned [simulating-simulink-models skill](https://github.com/matlab/simulink-agentic-toolkit/blob/c58e6aec7b904769ae43536e169d747feda95416/skills-catalog/model-based-design-core/simulating-simulink-models/SKILL.md), version 1.2, provides SimulationInput, Dataset input and SimulationOutput knowledge. Its manifest requires Simulink and no toolkit tools. Local E use is limited to normal serial runs of the reviewed flat scalar six-block D implementation, with current C approval, a frozen protocol, current required A operations and independent E operation/solver evidence. Historical D structure qualification is checked at its execution time with unchanged current identities; it does not grant new construction permission.

The pinned [authoring-simulink-inputs skill](https://github.com/matlab/simulink-agentic-toolkit/blob/c58e6aec7b904769ae43536e169d747feda95416/skills-catalog/simulink-simulation/authoring-simulink-inputs/SKILL.md), version 1.0, applies to an explicit request to synthesize new waveforms. It requires the toolkit tools `evaluate_matlab_code` and `model_read`. It does not govern loading measured CSV/MAT data or running a simulation. E consumes the protocol's approved finite scalar input values and declared interpolation/units; it does not invent waveforms, fill absent inputs or activate this skill's full generation workflow. Only the SKILL and manifest are pinned here; further authoring references and tooling require their own readback and qualification before use.

## Local execution boundaries

The upstream simulation guide assumes that a returned SimulationOutput is valid or that `sim` throws. E explicitly uses the R2025b `CaptureErrors` path to retain failed-run evidence. The local consumer checks ErrorMessage, ErrorDiagnostic, StopEvent, time coverage, finite outputs, dimensions and declared criteria separately from process exit and successful object return. Partial results and an early stop cannot establish primary-run success. The [R2025b SimulationMetadata API](https://www.mathworks.com/help/releases/R2025b/simulink/slref/simulink.simulationmetadata.html) and local [simulation assurance contract](../../core/simulation_assurance_contract.yaml) govern this boundary; no `isfield` assumption about a SimulationOutput is adopted.

The upstream prohibition on driving simulations with `load_system` does not prohibit E's owned-model readback. E loads only its isolated copy of the exact D-bound SLX after checking the source bytes and approved execution surface. SimulationInput carries simulation configuration; cleanup closes only the owned model without saving. Original SLX and C/D/parameter files must remain byte-identical, and global paths, other models and the base workspace remain outside the mutation scope.

The input-authoring guide requires a `createInputDataset` scaffold and permits a Dataset in the base workspace. That generation workflow is not activated by E's bounded data consumer. Local E constructs a Dataset from already declared protocol data in function scope, binds elements by root-port order, preserves the protocol's explicit units/interpolation and uses `setExternalInput`. It makes no claim to qualify the full authoring skill, its required tools, arbitrary signal types or its scaffold workflow.

Root-Outport `yout` Dataset logging and the retained SimulationOutput/MAT plus numeric exports are the bounded output path. Internal `logsout` marking, SDI, timetable/bus/trigger/function-call/multirate extensions, Fast Restart, acceleration, parallel runs, parameter sweeps and later analysis stay deferred. Solver candidates activate only on their own actual qualification; metadata cannot promote a failed or untested solver. Simscape, Stateflow, System Composer, other blocks and hierarchy builders remain deferred.

Upstream [license](https://github.com/matlab/simulink-agentic-toolkit/blob/c58e6aec7b904769ae43536e169d747feda95416/LICENSE.md) terms limit use to MathWorks offerings and require notices when redistributing. This adapter contains metadata and links; it vendors no upstream implementation.
